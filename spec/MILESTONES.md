# MILESTONES — בדיחה בלחיצה

**מסמכי מקור:** `PRD.md`, `ARCHITECTURE.md`, `DESIGN.md` (והתמונות `wireframes.png`, `style-guide.png`, `mockups.png`).

## עקרונות מנחים

- הפיתוח מיועד למסך מובייל אחד בלבד, בעברית וב-RTL, ללא תפריט או מסכים נוספים.
- מימוש לפי ה-Technology Stack שנבחר: React, TypeScript, Vite, CSS, Vercel Function, OpenAI Responses API במודל `gpt-5`, ו-`vite-plugin-pwa`.
- אין Database, Authentication, שמירת היסטוריה או Rate Limiting של המוצר.
- כל Milestone מסתיים בתוצר שניתן להריץ ולבדוק. רכיבי תשתית המוקמים לפני חיבור ה-AI לא יוצגו למשתמש כיכולת שכבר עובדת.
- ה-PRD גובר על רכיבים דקורטיביים סותרים בתמונות; בפרט אין לממש את אייקון התפריט שמופיע בחלק מה-Mockups.
- תהליך העבודה, האישורים והדחיפה ל-GitHub מוגדרים ב-`CLAUDE.md`. ה-Repository ב-GitHub כבר קיים ומחובר.

## מה צריך להכין לפני כל Milestone

| Milestone | מה בעלת המוצר מכינה |
|---|---|
| 1 | רצוי: תמונת חתלתול ב-`spec/assets/kitten.png` (ראה DESIGN 2.4.1). אם אין — משתמשים באיור זמני. |
| 2 | חשבון OpenAI עם אמצעי תשלום, **תקרת הוצאה חודשית והתראת תקציב מוגדרות**, ומפתח API שיש לו גישה ל-`gpt-5` — להדבקה בקובץ `.env`. בסוף ה-Milestone: חשבון Vercel (חיבור עם GitHub) לפריסה הראשונה. |
| 3 | טלפון Android וטלפון iPhone עם Chrome, לבדיקת ההתקנה וה-Offline. |
| 4 | אין הכנות חדשות. |

## Milestone 1 — הקמת פרויקט ומסך ראשי ✅

**שם ומטרה:** לבסס אפליקציית מובייל ניתנת להרצה עם המסך היחיד ועיצובו, לפני חיבור לשירות ה-AI.

**מה יש לממש:**
- יצירת פרויקט React + TypeScript עם Vite, תשתית CSS, וסידור Repository יחיד עבור Frontend ו-Backend בהמשך.
- מימוש מסך **"בדיחה בלחיצה"** בהתאם למבנה ה-Wireframes ולעיצוב ה-Style Guide וה-Mockups: כותרת, שדה נושא, לחצן **"צור בדיחה"** ואזור להצגת בדיחה, עם הטקסטים המחייבים שבטבלת הטקסטים ב-DESIGN.
- ממשק RTL בעברית, צבעי המותג (כולל Rose לכפתור), טיפוגרפיה, רכיבים מעוגלים ופריסת עמודה אחת.
- גופני Heebo ו-Assistant כקבצים מקומיים בפרויקט.
- תמונת החתלתול מ-`spec/assets/kitten.png`, או איור זמני לפי DESIGN 2.4.1 אם התמונה טרם סופקה.
- שדה נושא אופציונלי המוגבל ל-100 תווים, עם מונה תווים `0/100`.
- מצב ריק של כרטיס הבדיחה ("הבדיחה תופיע כאן לאחר הלחיצה").
- הגדרת תצוגת טקסט אזור הבדיחה כך שתתמוך גם בתוכן LTR ותוכן ארוך, ללא גלילה אופקית.
- עד לחיבור השירות, אין להציג בדיחות שמתחזות לתוצאה של GPT-5; הכפתור יישאר לא פעיל או יסומן בבירור כפונקציונליות שטרם חוברה בסביבת הפיתוח.

**תוצר מצופה:** אתר מובייל מקומי הנפתח ומציג מסך מעוצב ותקין; ניתן להזין ולערוך נושא, אך טרם ניתן להפיק בדיחה אמיתית.

**Definition of Done:**
- הפרויקט מותקן, נבנה ללא שגיאות TypeScript ונטען מקומית.
- כל ארבעת הרכיבים המרכזיים מופיעים במסך יחיד, בפריסה הדומה למקורות העיצוב וללא תפריט ניווט.
- כל הטקסטים במסך תואמים לטבלת הטקסטים ב-DESIGN.
- הממשק בעברית ו-RTL; הזנת 100 תווים מתאפשרת, ותו 101 אינו מתקבל; המונה מתעדכן בזמן הקלדה.
- הכפתור ב-Rose עם טקסט לבן קריא.
- תצוגת המובייל אינה גורמת לגלילה אופקית, וניתן לבדוק בה טקסט ארוך בשלב הפיתוח.
- אין מפתחות API או סודות בקוד הלקוח או ב-Repository.

## Milestone 2 — יצירת בדיחה מקצה לקצה ופריסה ראשונה

**שם ומטרה:** לספק את ה-Vertical Slice המרכזי: הזנת נושא, יצירת בדיחה חדשה ב-GPT-5 והצגתה באותו מסך — ולפרסם אותו לראשונה ב-Vercel, כדי שניתן יהיה לבדוק בטלפון אמיתי מ-Milestone 3.

**מה יש לממש:**
- מודול משותף ליצירת בדיחה, ו-Vercel Function ב-TypeScript עבור `POST /api/joke` כעטיפה דקה סביבו, כולל אימות קלט בצד השרת, טיפול בנושאים ריקים/רווחים והחזרת JSON לפי חוזה ה-API שב-ARCHITECTURE.
- הרצה מקומית ללא חשבון Vercel: שרת הפיתוח של Vite מנתב את `/api/joke` לאותו מודול (ראה ARCHITECTURE 3.1).
- שימוש ב-OpenAI SDK וב-Responses API עם הקבוע `OPENAI_MODEL = 'gpt-5'` ו-`reasoning: { effort: 'minimal' }`; הוראות המודל כוללות את כללי השפה, התוכן והנושא הבלתי הולם שב-PRD ו-ARCHITECTURE 2.5.
- זמני Timeout לפי ARCHITECTURE 2.5 (25 שניות לבקשה ל-OpenAI, 30 שניות ל-Function).
- שימוש ב-`OPENAI_API_KEY` ב-Backend בלבד, מקובץ `.env` שאינו נשמר ב-Git, עם `.env.example` ללא ערכים.
- חיבור הכפתור ל-`/api/joke` באמצעות בקשה חדשה בכל לחיצה, והחלפת הטקסט בכרטיס הבדיחה ללא שמירת היסטוריה.
- תצוגת בדיחה כ-Plain Text בכיווניות המתאימה לשפת התוצאה.
- **פריסה ראשונה:** בסוף ה-Milestone, Claude מדריך את בעלת המוצר צעד אחר צעד בחיבור ה-Repository ל-Vercel ובהגדרת `OPENAI_API_KEY` ב-Vercel Production. הפריסה מתבצעת עם הדחיפה ל-`main` שמאשרת את ה-Milestone.

**תוצר מצופה:** משתמש יכול להזין נושא או להשאיר את השדה ריק, ללחוץ על הכפתור ולקבל בדיחה אמיתית שנוצרה ב-GPT-5 — גם מקומית וגם בכתובת HTTPS ציבורית ב-Vercel.

**Definition of Done:**
- בדיחה בנושא בעברית מוצגת בעברית; בדיחה בנושא באנגלית (מילים או משפט) מוצגת באנגלית; נושא שהוא מילה זרה בודדת (למשל "iPhone") מפיק בדיחה בעברית; שדה ריק או רווחים בלבד מפיקים בדיחה כללית בעברית.
- נושא בלתי הולם מפיק בדיחה נקייה ולא הודעת סירוב.
- הבדיחה מגיעה בדרך כלל בתוך שניות ספורות.
- שתי לחיצות עוקבות לאחר השלמת הבקשה מפעילות שתי בקשות יצירה נפרדות, והבדיחה החדשה מחליפה את הקודמת בכרטיס הקיים (ללא הבטחה ששתי תוצאות המודל תהיינה שונות).
- API דוחה קלט שאינו תקין, לרבות נושא ארוך מ-100 תווים, גם אם נשלח ישירות ולא דרך הממשק.
- ה-API מחזיר את מבני התשובה והקודים המוגדרים בארכיטקטורה, ללא Cache של בדיחות.
- המפתח אינו מופיע ב-Bundle של ה-Frontend, בבקשות שיוצאות מהדפדפן או בתגובות ה-API.
- נבדקה גישה ממשית ל-`gpt-5`; אם אינו זמין לחשבון, עוצרים ומציגים למשתמש את החסימה — לא מחליפים מודל על דעת עצמנו.
- לאחר הדחיפה: כתובת ה-HTTPS ב-Vercel מציגה את המסך ומפיקה בדיחה.

## Milestone 3 — חוויית שימוש שלמה והפעלת PWA

**שם ומטרה:** להפוך את זרימת יצירת הבדיחה לאמינה וברורה במצבי טעינה, כשל וניתוק, ולאפשר התקנה ופתיחה Offline.

**מה יש לממש:**
- כל מצבי המסך לפי DESIGN 1.2: שורת סטטוס, "מכין לך בדיחה..." בזמן בקשה, כפתור מושבת במהלך ההמתנה ומניעת שליחת בקשות מקבילות מאותו לחצן.
- טיפול בשגיאות רשת, כשל Backend או שירות OpenAI והצגת ההודעות המחייבות; Timeout של 30 שניות בצד הלקוח; לאחר כשל ניתן לנסות שוב באופן יזום, ללא Retry אוטומטי שעלול להפיק חיוב כפול.
- הצגת **"נדרש חיבור לאינטרנט כדי ליצור בדיחה"** לפי כלל ההבחנה שב-ARCHITECTURE 2.6, תוך שמירה על זמינות מעטפת הממשק.
- הגדרת `vite-plugin-pwa`, Web App Manifest, אייקונים לפי DESIGN 2.4.1, Service Worker ו-Caching של קובצי המעטפת בלבד (כולל גופנים ותמונת החתלתול). אין לשמור תשובות בדיחה במטמון או באחסון מתמשך.
- בדיקת גלילה לקריאת בדיחות ארוכות ושימור פריסת מובייל.
- **בדיקה בטלפון:** התקנה ו-Offline אפשר לבדוק רק בכתובת HTTPS. לכן, אחרי שהבדיקות המקומיות עוברות, Claude עוצר ומבקש אישור לדחוף ל-`main` (כפי שמוגדר ב-`CLAUDE.md` עבור Milestone שדורש Push), ורק אז בעלת המוצר בודקת בטלפונים מול כתובת ה-Vercel.

**תוצר מצופה:** האפליקציה מוכנה לשימוש ולהתקנה כ-PWA, עם חיווי ברור במצבים הרלוונטיים ויכולת לפתוח את הממשק בלי אינטרנט לאחר טעינה/התקנה מוצלחת.

**Definition of Done:**
- בזמן יצירה ההודעה הנכונה גלויה ולא ניתן להפעיל בקשה נוספת באמצעות הכפתור; בסיום הבקשה הכפתור חוזר להיות זמין.
- כשל API/רשת מוצג בעברית, והבדיחה הקודמת והנושא נשארים; ניתן להפעיל ניסיון חוזר ולקבל בדיחה כאשר השירות חוזר לעבוד.
- בקשה שלא נענתה בתוך 30 שניות מציגה את הודעת השגיאה הכללית.
- לאחר שהאפליקציה נטענה ברשת ונכסי המעטפת נשמרו, ניתן לפתוח אותה ללא חיבור, עם הגופנים והתמונה; ניסיון יצירה במצב זה מציג את הודעת ה-Offline ולא יוצר בדיחה.
- ניתן להתקין את האפליקציה מכתובת ה-Vercel ב-Chrome על Android, ודרך "הוספה למסך הבית" ב-iPhone, בהתאם למגבלות iOS המתועדות בארכיטקטורה.
- בדיחות ונתוני נושא אינם נשמרים כנתונים עסקיים בין הפעלות, ותגובות `/api/joke` אינן נשמרות במטמון.
- מראה המצבים נשאר באותו מסך, ללא מודאלים/תפריטים/דפים חדשים.

## Milestone 4 — בדיקות קבלה סופיות ב-Production

**שם ומטרה:** לוודא שהאפליקציה הציבורית עובדת במלואה, מאובטחת ומוכנה לשימוש.

**מה יש לממש:**
- הוספת כותרות אבטחה (`X-Content-Type-Options`, `Referrer-Policy`, CSP שאינה חוסמת את ה-Service Worker) לפי ARCHITECTURE 2.8.
- וידוא `maxDuration: 30` ל-Function ו-Node.js Runtime.
- בדיקות קבלה בכתובת ה-HTTPS בדפדפן Chrome על Android ועל iPhone, כולל RTL, יצירת בדיחה, שגיאות, התקנת PWA והתנהגות Offline בהתאם לאפשרויות מערכת ההפעלה.
- בדיקת תגובות ללא Cache, זמינות Endpoint, וסיכוני העלות של שירות ציבורי פתוח ללא מכסת שימוש; אין להוסיף Rate Limiting בניגוד ל-PRD.

**תוצר מצופה:** האפליקציה זמינה לציבור ב-Vercel, ניתנת להתקנה במכשירים שבהם Chrome והמערכת תומכים בכך, וניתנת לעדכון באמצעות Push ל-GitHub.

**Definition of Done:**
- כתובת Production עם HTTPS מציגה את המסך היחיד וה-API פועל באותו Origin.
- בדיקות הקבלה של Milestones 1–3 עוברות בסביבת Production, לרבות שגיאות, נושא ריק, התאמת שפה, נושא בלתי הולם והחלפת בדיחה קיימת.
- כותרות האבטחה קיימות בתגובות, והאפליקציה וה-Service Worker עדיין עובדים.
- אין חשיפה של `OPENAI_API_KEY` ל-Frontend, ל-Repository או לתגובות API; הסוד קיים רק ב-`.env` המקומי ובהגדרות Vercel.
- Push מאושר ל-`main` מוביל אוטומטית ל-Production Deployment תקין ללא פעולה ידנית.
- נבדקו התקנה ופתיחה Offline במכשירים הנתמכים בפועל, ותועדו מגבלות אפשריות של Chrome ב-iPhone מבלי להבטיח זהות מלאה ל-Android.
- תקרת ההוצאה וההתראה בחשבון OpenAI מוגדרות; הובהר למשתמש ששימוש ב-OpenAI וב-Vercel עלול להיות כרוך בחיובים, וש-Vercel Hobby מיועד לשימוש אישי לא מסחרי.
